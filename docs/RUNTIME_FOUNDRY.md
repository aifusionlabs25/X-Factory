# Runtime Foundry v1.1

Runtime Foundry is the seventh Factory station. It turns a named candidate's owner-reviewed system prompt and knowledge core into a portable Hermes Desktop runtime package.

## What it creates

- A hash-bound runtime plan
- A unique Hermes profile blueprint for the named X-Agent
- An exact GPT-5.6 Luna canary prompt and payload
- An inactive one-call activation packet
- A provider-free local boundary-test console in Mission Control

## What it does not do

Creating the package does not install a Hermes profile, contact a model, enable tools or memory, read or change authentication, start ANAM, deploy, release, or approve production.

## Plain-English flow

1. The owner loads and reviews client material.
2. Knowledge Forge creates the personalized KB and system prompt.
3. Runtime Foundry seals those exact files into the agent's runtime plan.
4. The owner tests supported and unknown questions locally for free.
5. Porter includes the plan, profile blueprint, and canary artifacts in the generated repo.
6. A later guarded executor may run the single live Hermes/Luna canary only after a separately bounded activation.

The local console is deliberately not an LLM simulation. It proves which approved knowledge entry supports an answer and proves that unknown questions fail closed. The live canary is the next proof of actual model behavior.
