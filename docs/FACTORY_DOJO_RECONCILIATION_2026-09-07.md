# Factory and Dojo reconciliation

Reviewed September 7, 2026. This is a source-backed integration assessment, not an implementation or certification receipt.

## Destination

The owner supplies an opportunity. The Factory prepares the agent's identity, role, sourced Knowledge Bank, and tailored System Prompt. Dojo tests and improves an exact candidate. The owner reviews the resulting package and ANAM options. The Factory creates the approved ANAM persona through a verified integration, then validates that actual persona. Text chat, local repositories, and visualizations support this outcome; none replaces it.

## Build order and completion gates

1. Preserve a restorable baseline before integration: capture HEAD, staged/unstaged diffs, all untracked source/assets, and separately inventory project records. A commit alone omits untracked work. Current status shows extensive local changes. Create a checksummed archive and verify restoration into a temporary directory; exclude credentials and reconstructable caches with an explicit exclusion list. Do not call this assessment a completed backup.
2. Specify both specialist contracts, tools, workspace boundaries, failure behavior, and budget accounting. Have actual Troy execution draft their prompts from those briefs and existing designs. Preserve authorship receipts. Review with scenarios covering missing evidence, misleading transcripts, duplicate imports, tool failure, and budget exhaustion before installation. No third manager bot is needed.
3. Prove Librarian collection using a small ANAM export. Validate speaker order, dates/timezone, transcript completeness and persona snapshot availability. Retain originals; label missing configuration. Use session IDs plus content hashes to distinguish duplicates from updated records. Advance collection checkpoints only after the batch succeeds. Quarantine malformed rows and report counts. Keep coaching/regression/final-test partitions separated by session families, not just individual turns. Then expand to the last 30 days.
4. Prove adaptive Dojo planning and evaluation on one exact candidate. Combine fixed regression checks with newly generated role-specific scenarios. Keep expected answers and evaluator goals out of the target agent's inputs. Preserve raw/delivered outputs and identify infrastructure failures separately. Display actual model execution versus deterministic checks.
5. Prove one repair cycle: diagnose, route to the right specialist, produce a new version, rebuild, rerun the original failure, and run unseen challenges. Keep old evidence and candidate hashes. Stop on budget/time/round limits, regressions, no improvement, or required factual/authority decisions. Routine authorized draft iterations should not require repeated copy-paste approvals. Independent final evaluation cannot share the coach's reserved test set.
6. Consolidate one Factory Dojo destination with current stage, progress, readable report, optional manual chat, and next action. Old Lab concepts and current regression results become parts of this workspace, not competing applications. Only show real execution states. Add 3D/isometric visualization after the event model is reliable.
7. Verify ANAM's current persona-creation inputs and supported integration. Bind the reviewed prompt, knowledge delivery method, avatar/voice/model/settings, and identity to one creation preview. Do not assume an uploaded portrait is an ANAM avatar or that a bulk session export implies persona import support. Create after the relevant owner approval, retain returned persona IDs and configuration read-back, and test the actual ANAM channel. Local text PASS is not ANAM validation.

## End-to-end acceptance example

An owner provides an opportunity and receives a populated review package. After a local build, one Dojo action selects relevant historical cases, generates new challenges, captures a reproducible failure, creates a justified revision, and demonstrates both the repaired case and independent test results within a visible budget. An interruption preserves completed evidence and presents a clear resumable step without duplicate provider actions. The final reviewed package reaches an actual ANAM persona with verified settings. The owner never reconstructs knowledge in empty fields or carries messages between bots.

Before expanding to existing external agents, verify the adapter can bind their actual prompt, knowledge, tools, and runtime. Missing configuration means limited-scope evaluation, not an invented equivalence claim.
